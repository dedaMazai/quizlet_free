# Zubrika

Веб-приложение для изучения английского по карточкам. Продуктовый референс — [quizlet.com](https://quizlet.com), но приложение решает две задачи, которые Quizlet не закрывает: **учит фразами, а не изолированными словами**, и **планирует повторения**, чтобы выученное не забывалось.

---

## Зачем это, если есть Quizlet и Anki

| | Anki | Quizlet | Zubrika |
|---|---|---|---|
| Интервальные повторения | да | нет | **да** |
| Слово в контексте предложения | вручную | нет | **да, отдельный режим** |
| Обучение чанками (коллокациями) | вручную | нет | **да, с ИИ-подбором** |
| Порог входа | высокий | низкий | **низкий** |
| Готовые наборы | нет | 900 млн | нет (личные + шаринг) |

Позиционирование: гибкость колод как у Quizlet, память как у Anki, плюс контекст и ИИ, которых нет ни у одного из них.

### На чём основаны решения

- **Чанки эффективнее отдельных слов.** Обучение устойчивыми сочетаниями (коллокации, фразовые глаголы) развивает беглость сильнее, чем списки слов: готовая фраза снимает нагрузку на её порождение с нуля.
- **Контекст + активное припоминание + интервал.** Слово, выученное внутри предложения, удерживается дольше и лучше переносится в живую речь. Формат «пропуск в предложении» даёт припоминание именно в контексте.
- **Интервальные повторения — инфраструктура, а не украшение.** Без расписания повторов приложение умеет «выучить сегодня», но не умеет «не забыть через месяц».

## Что умеет

### Библиотека

- **Колоды** — создание, редактирование, дублирование, удаление.
- **Карточки** — слово, перевод, пример употребления, тип (**слово** или **фраза**), связь фразы с исходным словом.
- **Массовый ввод** — редактор на много строк с автопереводом (MyMemory API, дебаунс 500 мс) и озвучкой прямо в строке.
- **Импорт из Excel** — шаблон `.xlsx` скачивается из приложения; колонки читаются по позиции (A — слово, B — перевод, C — пример).
- **Экспорт** — Excel, JSON, Markdown.
- **Поиск дублей** — группировка одинаковых слов внутри колоды с массовым редактированием и удалением.
- **Избранное** — отметка слов звёздочкой; избранное можно учить как отдельную колоду, целиком или в рамках одной колоды.
- **Все слова** — сквозной список по всем колодам с серверной пагинацией и поиском по слову, переводу и примеру.
- **Глобальный поиск** на главной — по колодам и словам сразу.

### Режимы занятий

| Режим | Что делает | Чему учит |
|---|---|---|
| **Карточки** | Переворот карточки, стрелки, перемешивание, озвучка | Первое знакомство, узнавание |
| **Заучивание** | Раунды по 7 слов: сначала выбор из 4 вариантов, затем ввод с клавиатуры | Переход от узнавания к воспроизведению |
| **Письмо** | Ввод перевода в обе стороны (ru→en / en→ru), допуск одной опечатки | Точность написания |
| **Пропуски** | Слово скрыто внутри своего примера — нужно вставить его по смыслу | Припоминание в контексте, самый сильный формат по исследованиям |
| **Собери фразу** | Слова фразы перемешаны, собираются кликами | Порядок слов, беглость на чанках |
| **К повторению** | Сквозная очередь просроченных карточек по всем колодам | Удержание в долгой памяти |

«Заучивание», «Письмо», «Пропуски», «Собери фразу» и «К повторению» пишут результат в единое состояние повторения и в журнал статистики. Режим «Карточки» — ознакомительный: он ничего не записывает.

Шаг выбора из 4 вариантов проходится с клавиатуры: первый вариант выбран сразу, стрелки двигают выбор (←/→ — соседний вариант, ↑/↓ — соседний ряд), Enter отвечает выбранным, цифры **1–4** — сразу нужным. Номер варианта показан на самой кнопке; мышь работает как раньше.

### Интервальные повторения

- Алгоритм **SM-2 lite**: интервал растёт как `1 → 3 дня → ×ease`, фактор лёгкости в диапазоне 1.3–2.8, разброс ±5 % на длинных интервалах.
- Оценка выводится из самого ответа, кнопок самооценки нет: верно → `good`, опечатка → `hard`, ошибка → `again`.
- Прогресс хранится **на карточку**, а не на список: слово, выученное во «Всех словах», считается выученным и внутри своей колоды.
- Ошибка на выученной карточке возвращает её в очередь **текущей сессии**, а не откладывает до завтра.
- Шаги обучения живут в памяти сессии — в базу пишется только выпуск карточки и забывание.
- Бейдж с числом просроченных карточек в сайдбаре и карточка «К повторению» на главной.

### Прогресс

- Точность, число ответов, время изучения, текущая и рекордная серия дней.
- **Тепловая карта активности** за год в стиле GitHub.
- **Освоение слов** — распределение на новые / изучаю / усвоено.
- **Прогресс по колодам** — процент освоенности каждой колоды.

### ИИ

Обе функции работают через Supabase Edge Functions на `gpt-4o` с серверным лимитом запросов на пользователя (кредит списывается атомарно и возвращается при ошибке).

- **Проверка переводов** — ИИ оценивает корректность перевода, предлагает лучший вариант и **придумывает пример употребления** для каждого слова. Правки просматриваются в таблице и применяются выборочно.
- **Подбор фраз** — к выбранным словам (до 10 за вызов) подбираются 2–3 частотные коллокации с переводом и примером. Они сохраняются как карточки-фразы, связанные с исходным словом, и сразу готовы для режимов «Пропуски» и «Собери фразу».

### Совместная работа

- Колодой можно поделиться по email.
- Владелец решает, могут ли гости править слова.
- Гость видит автора, может скопировать колоду себе или убрать её из своих.
- У каждого свой прогресс по общей колоде.

### Озвучка

Web Speech API без внешних сервисов: озвучка слов и примеров в любом режиме, выбор голоса в настройках с предпрослушиванием.

### Аккаунт и администрирование

Регистрация по email, профиль с аватаром-пресетом, светлая и тёмная темы, интерфейс на русском и английском. Роли `admin` / `user`: администратор управляет пользователями, ролями, блокировками и персональными лимитами ИИ-запросов.

## Технологии

React 19, TypeScript 5.9, Webpack 5, Redux Toolkit + RTK Query, Ant Design v6, SCSS + CSS Modules, React Router v7, i18next (ru/en), Chart.js, Sentry.

Бэкенд — **Supabase**: Postgres с построчной изоляцией данных (RLS), авторизация, Edge Functions на Deno.

```
src/
├── app/        # Провайдеры (Store, Router, Theme, Notification, ErrorBoundary), глобальные стили
```

## Настройка бэкенда

Схема ведётся вручную, миграций нет. SQL-скрипты из `supabase/` выполняются в Supabase SQL Editor **в этом порядке** (все идемпотентны):

```
sharing.sql → shared_edit.sql → roles.sql → block.sql
→ statistics.sql → ai.sql → cards.sql → chunks.sql → srs.sql
```

`contacts.sql` (контакты, уведомления, шаринг колод контактам) выполняется после `privacy.sql`.

`srs_cleanup.sql` выполняется отдельно, через 1–2 недели после `srs.sql`, когда подтвердится, что новая таблица повторений наполняется.

Edge Functions:

```bash
supabase functions deploy check-translations
supabase functions deploy generate-chunks
supabase secrets set OPENAI_API_KEY=sk-...
```

Переменные окружения фронта — `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `MYMEMORY_EMAIL`. Шаблоны: `env/development/.env.example` и `env/production/.env.example`.

## Локализация

Все пользовательские строки — через `useTranslation` (`react-i18next`). Языки: `ru` (основной) и `en`, ключами служат сами русские фразы. Файлы переводов — в `public/locales/`.

### Скрипты для работы с переводами (`scripts/`)

В папке `scripts/` находятся три скрипта для управления i18n-переводами. Все работают в двухфазном режиме: сначала генерируют MD-отчёт для ревью, затем применяют изменения из отредактированного отчёта.

#### Полный workflow

```bash
# Шаг 1. Очистка — удалить неиспользуемые ключи из переводов
node scripts/clean-translations.js
# → Генерирует scripts/clean-translations-report.md
# → Проверить отчёт, удалить строки с ключами, которые нужно ОСТАВИТЬ
node scripts/clean-translations.js --apply
# → Применяет изменения из отчёта: удаляет из ru и en, добавляет недостающие в en

# Шаг 2. Поиск — найти ключи в коде, которых нет в переводах
node scripts/find-missing-translations.js
# → Генерирует scripts/translation-report.md
# → Проверить отчёт, удалить строки с ключами, которые НЕ нужно добавлять
node scripts/find-missing-translations.js --apply
# → Добавляет ключи в ru (значение = ключ) и en (значение = пустая строка)

# Шаг 3. Перевод — заполнить пустые английские переводы
node scripts/find-empty-string-in-json-en.js
# → Генерирует scripts/empty-translations-report.md с ru-значениями для контекста
# → Отдать отчёт AI или переводчику — заполнить строки после **en:**
node scripts/find-empty-string-in-json-en.js --apply
# → Вставляет заполненные переводы в en/translation.json
```

---

#### `clean-translations.js` — очистка неиспользуемых ключей

Анализирует файлы переводов (`public/locales/`) и исходный код (`src/`):

1. **ru → код**: каждый ru-ключ ищется в исходниках. Если не найден — помечается на удаление. Англоязычные ключи (ответы от бэкенда) пропускаются автоматически
2. **en → ru**: каждый en-ключ проверяется на наличие в ru. Если нет — помечается на удаление
3. **ru → en**: каждый ru-ключ проверяется на наличие в en. Если нет — помечается на добавление

При `--apply` также удаляет из en ключи, удалённые из ru, чтобы не оставалось сирот.

**Отчёт:** `scripts/clean-translations-report.md` — удалите строки с ключами, которые хотите **оставить**, перед запуском `--apply`.

---

#### `find-missing-translations.js` — поиск недостающих ключей

Сканирует все `.ts`/`.tsx` файлы в `src/` и находит проблемы:

| Тип | Описание | Попадает в отчёт |
|-----|----------|-----------------|
| `MISSING_KEY` | Ключ в `t('...')` / `<Trans>` отсутствует в `translation.json` | Да |
| `WRONG_INTERPOLATION` | Используется `t(\`...\${var}...\`)` вместо `t('...{{var}}...', { var })` | Нет (только консоль) |
| `UNWRAPPED` | Русский текст в строковом литерале без `t()` | Нет (только консоль) |
| `JSX_TEXT` | Русский текст напрямую в JSX без `t()` | Нет (только консоль) |

Игнорирует: комментарии, `console.*`, `import`/`export type`/`interface`, тесты, stories, `.d.ts`.

**Отчёт:** `scripts/translation-report.md` — удалите строки с ключами, которые **не нужно** добавлять, перед запуском `--apply`.

При `--apply` добавляет ключи в оба файла: ru (значение = сам ключ) и en (пустая строка).

---

#### `find-empty-string-in-json-en.js` — заполнение пустых en-переводов

Находит ключи в `en/translation.json` с пустым значением (`""`) и генерирует отчёт с ru-значениями для контекста.

**Отчёт:** `scripts/empty-translations-report.md` — формат для AI/переводчика:

```markdown
### `Ключ перевода`

**ru:** Русское значение для контекста

**en:** (сюда вписать английский перевод)
```

При `--apply` парсит заполненные строки `**en:**` и вставляет переводы в `en/translation.json`.
